PACCHETTO TESTER + RELEASE — istruzioni per chi distribuisce
============================================================

Il repo e' pubblico: niente token, niente account per i tester.

1. PREPARA LO ZIP PER I TESTER
------------------------------
Metti in uno zip questi file (e nient'altro):
  installer/Installa-Orchestra.bat
  installer/scarica-release.ps1
Il tester lancia Installa-Orchestra.bat: non serve Git né account GitHub.
Gli serve solo: Windows, internet, e le chiavi API da mettere in .env
(il file .env si crea da solo al primo avvio, da .env.example).

2. PUBBLICA UNA RELEASE (a ogni aggiornamento)
----------------------------------------------
  - alza __version__ in orchestra/__init__.py e committa
  - git tag v0.6.0 && git push --tags
  - gh release create v0.6.0 --generate-notes
Da quel momento tutti i tester ricevono l'update al prossimo avvio
(Avvia-Orchestra.bat fa update --auto prima di partire).

NOTE
----
- .env, budget, storico e goals dei tester non vengono mai toccati
  dagli aggiornamenti (lista CONSERVA in orchestra/update.py).
- Prima di una release, fai girare python tests/run_all.py col server acceso.
- Se un giorno il repo tornasse privato, orchestra update supporta
  ancora un token read-only via env ORCHESTRA_UPDATE_TOKEN o token.txt.
