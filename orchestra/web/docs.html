Avvio rapido

Orchestra è un orchestratore agentico locale, senza dipendenze esterne per il core (stdlib Python). Oltre alla CLI, ha una web UI con chat, tool stream, benchmark, onboarding, goal persistente.

cp orchestra/.env.example orchestra/.env
# imposta provider (OPENROUTER_API_KEY, ORCHESTRA_MODEL, …)
python3 -m orchestra.cli doctor
python3 -m orchestra.cli web                # http://127.0.0.1:8737
python3 -m orchestra.cli chat               # sessione CLI
python3 -m orchestra.cli web --no-browser   # senza aprire browser

Comandi GUI: python3 kill_ports.py 8737, poi python3 -m orchestra.cli web.

Configurazione

La configurazione vive in orchestra/.env e resta solo sul tuo computer:

  • ORCHESTRA_PROVIDER=openrouter|nous|groq|nvidia|anthropic|...
  • ORCHESTRA_MODEL=...
  • chiavi provider (OPENROUTER_API_KEY, NOUS_API_KEY, …)
  • ORCHESTRA_ROOT / ORCHESTRA_HOME (root task e dati)

Nous può connettersi via OAuth device-code (python3 -m orchestra.cli auth nous), senza incollare chiavi.

Modelli & provider

Il selettore modello in UI aggiorna il modello senza riavviare il server. Un provider/scambio a metà turno è respinto (409) per coerenza della conversazione.

  • Elenco filtrabile per provider/free/categoria.
  • Switch provider aggiorna anche fallback chain (non solo provider attivo).
  • Verifica versione servita e se il backend la supporta (pricing, tool calling).

Onboarding web

Modal “Cosa fai con Orchestra?” compare solo alla prima apertura. Sceglie ambito, profilo strumenti e prompt iniziale (repository, sito web, dati, app, docs, automazione, debug, ricerca, pianificazione, design, ecc.).

  • Pulsante header “Cosa fai?” riapre sempre (anche dopo “Salta”).
  • Applicazione: profilo → scope → prompt draft → invio.
  • Scegliere una categoria e compilare i dettagli crea un vero goal (thread in background) e apre il pannello Obiettivo per seguire il progresso.
  • Persistenza del flag salta via localStorage.

Progetti

La sidebar ha un selettore “Progetto” che filtra memoria e cronologia per progetto. All'avvio Orchestra rileva il progetto attivo dalla directory di lavoro; il selettore si aggiorna automaticamente (refresh non azzera più il progetto attivo).

  • Aggiungi/gestisci progetti dal modal (pulsante nella sidebar): nome + directory.
  • Il progetto attivo determina quali fatti di memoria e conversazioni vengono considerati.
  • Persistenza in ORCHESTRA_HOME/progetti.json.

Interfaccia web

Chat streaming

Eventi real-time, tool richiudibili, contatori token, annulla, nuova conversazione, ragionamento separato.

Opzioni

Servizio/modello, chiavi, budget, skill, permessi, servizi gratuiti, dipendenze.

Goal bar

Input obiettivo + Avvia/Prossimo/Stop. Le opzioni avanzate (profilo, kind, priorità, dipendenze, max iterazioni, criteri, recovery) sono collassate. All'avvio il pannello si apre da solo e fa polling ogni 2s; cliccando una riga si vede l'ultimo output e il gate (ok/bocciato/parziale/in attesa).

Steer

Mentre il modello lavora, la barra Steer compare sopra il campo di scrittura: il messaggio che invii viene consegnato al modello subito dopo il tool o il ragionamento in corso, senza fermare il turno. Utile per correggere la rotta senza ricominciare.

Stop

Il pulsante ■ accanto a Invia ferma il turno. Il cancel viene controllato a ogni iterazione e prima di ogni tool: i tool non ancora eseguiti ricevono un risultato "cancellato" e il turno si chiude pulito, senza lasciare buchi nella sequenza.

Tracce

La sidebar (pulsante 📼) elenca gli ultimi turni con l’esito in parole — «completato», «fermato al limite», «annullato», «budget finito», «girava a vuoto», «troppi errori», «verifica fallita», «solo parole, niente fatti», «fermato su un annuncio». Cliccando una riga si apre un modale con la sequenza esatta degli eventi: serve per capire perché un turno è andato com’è andato, senza ripeterlo.

Steer e Stop

Due modi per intervenire su un turno mentre il modello lavora, senza aspettare che finisca.

Steer — correggere la rotta a metà lavoro

La barra Steer compare sopra il campo di scrittura solo durante un turno attivo. Quello che scrivi viene messo in coda e consegnato al modello alla prima occasione utile: subito dopo il tool o il ragionamento in corso, prima della chiamata successiva al modello.

  • Il turno non viene interrotto: lo steer si innesta nel flusso esistente.
  • Limite di 5 messaggi steer per turno, 2000 caratteri ciascuno.
  • Se il modello stava per concludere, lo steer lo fa riprendere.

Stop — fermare il turno

Il pulsante ■ accanto a Invia ferma il turno in corso. Il controllo di cancellazione avviene a ogni iterazione e prima di ogni tool: se il modello aveva chiesto dieci tool e ne hai eseguiti tre, i sette rimanenti ricevono un risultato "cancellato" e la sequenza resta valida.

Il turno si chiude come annullato, senza lasciare tool_call senza risultato.

Tool & profili

I tool sono separati da profili per evitare token sprecati. `pieno` riattiva tutto. Profili: base, ricerca, skill, pieno o auto.

PROFILI = {
  "base": read/write/list/run_shell/calc + memoria,
  "ricerca": base + web_cerca/web_leggi + storico,
  "skill": skill tools,
  "pieno": tutti i tool registrati
}

Tool aggiunti: browser (browser_apri, browser_render, browser_screenshot), computer (computer_screenshot, computer_click/type/open), web, shell, memoria, skill, storico, goal via API/UI non tool. read_file supporta start_line/end_line per intervalli precisi; web_leggi tronca alle prime N righe.

Multi-agent & delega

Il padre può delegare subtask a figli on-demand se il tool delega è registrato (aggiunto in `default_registry` solo con profilo/condizioni appropriate). Delega best-effort: fall-back se catalog o modello non disponibile.

  • Profondità max, # figli limitato.
  • Costo per figlio aggiunto al resoconto (se catalogo).
  • Il figlio non può delegare a sua volta (tetto profondità).
  • Recovery opzionale nei goal: recovery={max_retry, modelli_alternativi, accorcia_contesto}. Di default nessun retry; i tetti strutturali non si ritentano mai.

Goal autonomi

Layer persistente JSON in ORCHESTRA_HOME. Stati: pending, running, done, failed, cancelled. I piani kind=piano sono contenitori: non eseguono agenti e si chiudono da soli quando i figli finiscono.

Come si usa (interfaccia web): pulsante “Obiettivo” apre il pannello. Scrivi l’obiettivo, premi Avvia. Il goal parte in background e il pannello mostra stato, gate e ultimo output; clicca una riga per i dettagli. “Prossimo” esegue a mano il prossimo goal pronto; “Coda on/off” attiva lo scheduler automatico. Opzioni avanzate (profilo, kind, priorità, dipendenze, max iterazioni, criteri, recovery) sono collassate.

Comandi CLI ed endpoint REST per questa funzione sono nell’appendice per sviluppatori.

  • Thread daemon, massimo iterazioni (default 60), timeout pre-process massimo.
  • Stop condition: risposta finale, fallimento provider/tool, max iterazioni, timeout.
  • Gate di accettazione: solo risposta_finale non vuota diventa done, salvo --consenti-parziale o criteri dichiarativi superati. Nel pannello il badge gate mostra ok / bocciato / parziale / in attesa.
  • Retry limitato con backoff fino a max_attempts; dipendenze circolari rifiutate; un goal non pronto non parte nemmeno se avviato direttamente.
  • Pannello Obiettivo: creazione con piano/retry/criteri, lista con gate visivo, pulsante Prossimo e coda automatica on/off.
  • Coda automatica spenta di default (spende token veri): un solo consumatore alla volta.
  • UI poll 2s solo se esiste goal running.

Cron — job programmati

Pannello “Cron” (toolbar) per schedulare obiettivi o comandi shell. Frequenze tramite menu amichevole (ogni 5/10/30 min, ogni ora, due volte al giorno, una volta al giorno, orario preciso, personalizzato cron). Lo scheduler parte in automatico all'avvio del server (intervallo 30s) e riprende dopo riavvio (job salvati su disco). Avvio automatico di Orchestra su Windows (al login) attivabile dal pannello.

  • Tipi azione: goal (avvia un obiettivo) o shell (comando).
  • CRUD completo da UI e via tool cron (anche per l'agente).
  • Shortcut: @hourly, @daily, @weekly, @monthly, @yearly, @reboot.

Client MCP

Orchestra può connettersi a server MCP esterni (Supabase, Unreal, Godot, filesystem, ecc.) e usare i loro tool come strumenti nativi. Pannello “MCP” in toolbar per aggiungere/configurare server stdio; i tool scoperti diventano disponibili con prefisso mcp_<server>__<tool>. Gestione anche via tool mcp.

  • Configurazione persistente in ORCHESTRA_HOME/mcp_servers.json.
  • Connessione automatica dei server abilitati all'avvio.
  • Supporto transport stdio (subprocess); SSE/HTTP in roadmap.

Browser & computer use

Sfruttano SOLO componenti OS già presenti (Chrome/Edge, PowerShell, .NET). Non richiedono pacchetti esterni.

  • browser_render: headless Chrome/Edge (JS eseguito), fallback fetch leggero.
  • browser_screenshot: PNG nel workdir.
  • screenshot_view: legge quel PNG e lo mostra al modello come immagine — senza, il modello riceve un percorso e non vede nulla.
  • Automazione click/type/open gated da permesso o env ORCHESTRA_COMPUTER_USE.

Per i tester: l’automazione da tastiera/click richiede conferma esplicita; di default bloccata finché non si abilita.

Permessi

I file fuori dalla cartella di lavoro richiedono conferma. In web, un modal chiede “una volta/sessione/sempre/mai”. In assenza di canale (CLI/benchmark) il default è negare.

Creazione nuove chiavi API: esse non devono arrivare ai subprocessi (scrub env).

Memoria & storia

  • memoria ricercabile via tool (memoria), sezioni Importanti/Fatti, anti-duplicati.
  • storico conversazioni persistente, search via tool (storico_cerca).
  • non iniettata nel prompt: l’agente la cerca su richiesta.
  • Ottimizzatore: potatura dei fatti mai usati (dopo grace period), dedup case-insensitive, unione opzionale (richiede provider). Si avvia automaticamente ogni 20 turni e via tool/azione ottimizza (anche dry_run).
  • Indice FTS5 su SQLite: la ricerca non dipende dalla dimensione del file.

Budget & limiti

Budget trasversale (costo per turno/complessivo) applicato a tutte le chiamate. Il consumo ha una sola porta; contatori su disco per giorno/mese; limite 0 ammesso (distingue “scritto 0” da “non scritto”). Verifica l’identità del contatore condiviso (a is b) e il limite applicato, non solo quello salvato.

Accesso remoto (telefono, fuori casa)

Orchestra gira sul tuo PC. Per usarlo dal telefono anche fuori casa serve esporlo in sicurezza: il server ha un accesso remoto con token e, se vuoi, un tunnel automatico.

  • Avvia con orchestra web --remote: il server ascolta su tutte le interfacce, genera un token e lo stampa a console. Lo stesso token viene salvato in orchestra/.env (ORCHESTRA_REMOTE_TOKEN).
  • Per un URL pubblico (senza VPN): orchestra web --tunnel. Se cloudflared e' installato, Orchestra apre il tunnel da sola e stampa l'URL https://…trycloudflare.com. Su Windows, se manca, Orchestra propone di installarlo automaticamente con winget; in caso contrario stampa le istruzioni e ripiega sull'IP della LAN.
  • Sul telefono apri l'URL e inserisci il token nella pagina di login. La sessione resta valida (cookie).
  • In alternativa, senza tunnel: una VPN privata (es. Tailscale) tra PC e telefono, poi orchestra web --remote e apri http://<ip-tailscale-del-pc>:8737.
  • Sicurezza: il token protegge tutte le rotte. In locale (127.0.0.1) l'accesso resta libero come prima. Le chiavi API non lasciano il PC.
  • Puoi anche avviare il server remoto direttamente dall'interfaccia: scheda Opzioni → Remoto → "Avvia remoto (LAN)" oppure "Avvia tunnel (pubblico)". Non serve aprire il terminale: il pulsante lancia un secondo server in background e mostra URL + QR code. "Ferma" lo spegne.
  • Nella scheda Opzioni → Remoto vedi token, URL e un QR code da scansionare.
  • Sul telefono l’interfaccia si adatta da sola (sidebar richiudibile, chat a tutta larghezza). Orchestra è installabile: dal browser del telefono «Aggiungi a schermata Home», e si apre a schermo intero come un’app nativa (manifest + service worker, con cache offline della shell).

Se qualcosa non va

  • Orchestra risponde su 127.0.0.1:8737. Se il browser dice che il sito non è raggiungibile, il server è spento: riapri “Avvia Orchestra”.
  • Se hai avviato il server più volte, chiudi le altre finestre: due processi sulla stessa porta danno comportamento intermittente.
  • Pagina bianca o pulsanti che non rispondono: ricarica con Ctrl+F5.
  • Per capire se il server è vivo, apri http://127.0.0.1:8737/docs: se questa guida si apre, il server c’è.

Installazione senza GitHub

Pacchetto da passare ai tester: installer/Installa-Orchestra.bat + installer/LEGGIMI.txt (il bat è autonomo — vedi installer/LEGGIMI.txt).

  • L’installer controlla Python, scarica l’ultima release, crea .env da esempio e mette “Avvia Orchestra” sul Desktop. Niente Git, niente account.
  • Avvia-Orchestra.bat aggiorna, avvia il server in background e apre il browser; se riaperto a server acceso chiede Apri / Riavvia / Ferma.
  • orchestra update --check controlla soltanto; chiavi e dati locali non vengono mai sovrascritti.
